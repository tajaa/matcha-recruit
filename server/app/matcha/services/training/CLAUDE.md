# Training — feature spec(s)

Moved verbatim from root `CLAUDE.md`'s Feature Flags table. Root keeps a one-line summary + `→ full spec:` pointer here. Default column below matches `DEFAULT_COMPANY_FEATURES` in `server/app/core/feature_flags.py`.

## `training` (default ❌)

Training programs. Requirements are assigned by **provenance** (`training_records.source_type` — `manual`/`bulk_assign`/`rule`/`new_hire`/`incident`/`discipline`/`credential`/`cadence` — + `source_ref` pointing at the triggering row), evaluated by the shared `services/training/training_assignment.py` (`resolve_audience` + `assign_training`, pool-free-safe — takes `conn` explicitly so it works unchanged from Celery). Company-authored `training_assignment_rules` (trigger `new_hire`/`incident`/`schedule`/`scheduled_role`) drive auto-assignment: new hires enroll at hire time (hook in `employees/crud.py`, `bulk_upload.py`, `hris_sync_orchestrator.py`), incident close matches `trigger='incident'` rules against `involved_employee_ids` (`training_assignment.on_incident_closed`, called from both `services/ir/ir_copilot_flow.py:_close_incident_via_copilot` and the generic `PUT` in `ir_incidents/crud.py`), and `training_cadence.py`'s worker gained a rule-agnostic `trigger='schedule'` pass alongside its original CA/SB-1343 hardcode (unchanged for back-compat). **Scheduling → training** (migration `trainsched01`): `trigger='scheduled_role'` rules (`training_assignment_rules.roles`, matched case-insensitively against a shift's `role`) auto-assign the first time an employee is scheduled into a matching role — due by the shift's start date — via `evaluate_scheduled_role_rules`, hooked (try/except-logged, never fails the scheduling write) into shift assign/swap-approve/create-with-assignees in `routes/employee_schedule/`. Separately, a `kind='training'` shift (`schedule_shifts.training_requirement_id`) IS the requirement — assigning an employee creates/accelerates their record directly instead of matching rules. Both stamp `source_type='schedule'`. The assignment-time compliance gate (`routes/employee_schedule/_compliance.py:check_shift_compliance`) also runs a `training_lapse`/`credential_lapse` **advisory** (never a block — no statute behind a training gap) via the shared `schedule_intelligence.fetch_lapse_items`, which also powers `qualified_coverage` and the week-view roster-picker lapse badges (`GET /employee-schedule/week` → `roster_flags`). **Incident → training has three paths**: admin action (`POST /ir/incidents/{id}/assign-training`, `IRAssignTrainingPanel.tsx`), Copilot-suggested (deterministic `assign_training` Copilot action type — grounded on `RecommendationsAnalysis.training_topics` word-overlap matched against `training_requirements` via `_auto_map_training_topics`, analysis_type `training_mapping` in `ir_incident_analysis`; **never LLM-proposed** — the prompt schema in `ir_ai_orchestrator.py` doesn't advertise it, avoiding a hallucination surface on a legal record), and the auto-rule above. `ir_corrective_actions.action_type` gained a `'training'` value + `training_requirement_id`. **Discipline → training**: `progressive_discipline.remedial_requirement_id`, set at issue time by `discipline_engine.issue_discipline_with_supersede`, assigns `source_type='discipline'` in the same transaction; `GET /discipline/records/{id}` returns the linked record's status. **Credential parity**: `training_records` gained `waived_at/by/waiver_reason` (`POST /training/records/{id}/waive`), mirroring `employee_credential_requirements`; the credential-lapse→refresher mapping itself is deferred. **Evidence wiring**: `epl_readiness.py`'s `harassment_training` factor separately counts remedial completions; `services/pilots/legal_defense/`'s training citations carry `source_type`/`source_ref`; `services/pilots/hr_pilot_corpus/` / `matcha_work_mode_contexts.py` annotate remedial rows (`_SUPERVISOR_ONLY_SOURCES`-gated, so Ask HR never sees them). Employee detail page has a **Training tab** (`EmployeeTrainingPanel.tsx`) showing per-record provenance + waive/assign actions.

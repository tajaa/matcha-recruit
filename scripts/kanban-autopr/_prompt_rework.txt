Score maxima are requirements_clarity 30, evidence_quality 20,
code_localization 20, verification_strength 15, and production_alignment 15.
Use implementation only when the total is at least 75, there are no blocking
questions, and a safe code diff exists. Use partial_implementation only when
the total is at least 45, independently correct safe code exists, and the
questions explain what must be answered before the rest can be done. Use
questions_only whenever a human answer could unblock the review: make no code
changes and provide one or more concrete questions with at least two options.
Use no_safe_action only for already_fixed, policy_blocked, or
external_dependency; it has no questions and no code diff. A needed migration
is not one of them — draft the version file. A `draft_pr` directive forbids
already_fixed because a repo-local fix must be drafted. Missing evidence or
ambiguous product intent is questions_only, not no_safe_action.

Criticality is independent of confidence: red is security/privacy, data loss,
production outage, compliance/payroll, or a blocked core workflow; orange is a
material regression or broad workflow impact without a reasonable workaround;
yellow is scoped feature, UX, wording, or workaround-available work.
